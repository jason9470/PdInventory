# 欄位選項化盤點

> 目的：找出目前是自由文字輸入、但實際上只會有固定幾種答案的欄位，改成下拉或勾選，
> 以減少打字錯誤與寫法不一致。
>
> 方法：直接統計資料庫現有資料的相異值，再逐欄判斷。
> **筆數不多，統計結果只能說明「目前出現過什麼」，不等於「將來只會有什麼」**
> —— 每一組選項都要請填表單位確認後才定案。
>
> ⚠ **本文的統計數字是 0902 匯入之前的**（InfoSystems 33 筆、InventoryItems 21 筆、
> TransferRecords 51 筆）。0902 匯入後 SW 增為 55 筆、DA 獨立成表共 62 筆，
> 各欄的分佈已經改變，已完成的結論不受影響，但**尚未處理的項目要重新統計一次**。
> 匯入時新出現的值（與AD整合的三種帶括號說明的「否」、RTO 的 15／30 分鐘、
> RPO 的 30分鐘／3小時／不適用）已加入選項。

## 跨表共通問題

### 1. 多值欄位用了五種分隔符號

| 符號 | 出現的儲存格數 |
|------|--------------|
| `/` | 352 |
| `,` | 99 |
| `;#` | 55 |
| `、` | 41 |
| `;` | 35 |

最能說明問題的例子 —— 「信義IDC 加 板橋IDC」這一個組合，在同一套系統裡有三種寫法：

```
SW-位置：信義IDC;板橋IDC (7 筆)   信義IDC/板橋IDC (7 筆)
DA-位置：信義IDC;#板橋IDC (4 筆)
```

（`DA-位置` 已與 `SW-位置` 合併，這裡保留當時的統計是為了說明寫法有多分歧。）

`;#` 是 SharePoint 多選欄位的匯出格式，`/` 與 `;` 則是人工輸入。
**改成複選之後這個問題會自然消失**（存的是選項 Id，畫面才組字串），
這也是把多值欄位選項化最大的好處。

### 2. 兩個欄位應該自動計算，而非輸入（已完成）

`SW-資產價值` 與 `DA-資產價值` 都等於該表的機密性＋完整性＋可用性，
**63 筆全部相符，零例外**。兩欄已合併為一，並改為自動計算。

### 3. 弱關聯的資產編號應該改成下拉（已完成）

`InventoryItems.資產編號` 與 `TransferRecords.資產編號` 原本是自由輸入，
但值全部對得到 `InfoSystems.SystemCode`。個資盤點、風險自評、拋轉清單三張表單的
新增與編輯畫面都已改為從資訊資產清單挑選（見 `Helpers/AssetPicker.cs`）。

三個實作重點：

- **資產名稱不採信畫面送回來的值**，一律由伺服器端依編號查出後寫入。
  否則使用者改了編號沒改名稱，兩者就會對不起來——實測時就發現既有資料裡
  `InventoryItems` 存的是「AMS 帳戶系統」，`InfoSystems` 卻是「AMS帳戶系統」，
  現在存檔一次就會自動對齊。
- **編號已不在清單中的舊資料仍會保留**：下拉會多出一個標示「已不在資產清單中」的選項並選中它，
  不會因為選不到而在存檔時被清成空白。
- **風險自評的編輯畫面原本不寫回資產編號**，現在會寫回，編號 19～21 那三筆
  （只存在於風險自評、個資盤點表沒有的資料）因此才維護得了。

### 4. ~~N/A 到底代表什麼~~ —— 已確認

全系統有 **11 個欄位整欄都是 `N/A`**（系統盤點 9 個、拋轉清單 2 個）。

**2026-09-03 業務端確認：`N/A` 照原樣保留即可**，不必再細分「不適用／未填寫／沒有」。
因此這 11 欄選項化時直接把 `N/A` 當成一個正常選項，不做轉換、不另設空值語意。
